# 核心交互物品建模计划表

- 更新日期：2026-08-02
- 状态：已批准，待执行
- 制作假设：单人负责建模、材质、锚点、导出与 Godot 交互校准
- 预计总工期：28–39 个工作日
- 建模基线：Blender 4.5.5 LTS

## 1. 目标与边界

本计划覆盖 `assets/asset_manifest.json` 中现有 16 项交互资产，以较高交互精度完成 M1 可接入候选。视觉基线来自《美术设计案》：低多边形复古 3D、远距离可识别、轮廓明确、手绘基础色、AO 辅助和简单 PBR 参数；现实世界以暖色生活感为主，眼镜世界通过同一几何的材质覆盖表现低饱和、冷静和时间痕迹。

本计划不包含人物、酒柜、吊灯、墙面、地板等非清单环境资产，不批准正式配方、平衡值或最终美术。设计案中的 `500–10000` 面是单件资产的指导范围，不是硬性目标；增加面数不能替代轮廓识别或交互准确性。

本轮只建立生产与验收计划，不把任何资产误报为已建模或已接入。灰盒必须保留到对应正式候选通过运行与截图验收后。

## 2. 状态与负责人规则

统一负责人记为“单人建模/技术美术”。每项资产只能使用以下状态：

- `未开始`：尚未建立尺寸卡或草模。
- `草模中`：正在确认尺度、轮廓、原点和接触面。
- `制作中`：进行正式低模、UV、材质和锚点制作。
- `技术验收`：检查单位、轴向、变换、命名、锚点和 GLB。
- `美术评审`：检查风格、材质语言、磨损和双世界表现。
- `交互验收`：在 Godot 检查握持、摆放、倾倒、液面、碰撞和命中范围。
- `M1 候选`：全部验收通过，但灰盒仍保留到批次运行复核结束。
- `待返修`：任一道验收门失败并记录明确返修原因。

## 5. 六道验收门

每件资产必须按顺序通过，失败时进入 `待返修` 并记录问题、负责人、目标修复批次和复验结果。

### 5.1 尺度与轮廓草模

- 对照当前灰盒尺寸、第一人称视角和相邻物体建立尺寸卡。
- 确认底部接触面、原点、主要朝向和远距离剪影。
- 传统滤具等尚无最终造型的物品必须先获得造型确认，再进入正式制作。

### 5.2 技术验收

- 米制，应用缩放与旋转，Godot 前向 `-Z`、上方 `+Y`。
- 文件名、根节点和稳定 ID 与 `asset_manifest.json` 一致。
- 仅包含所需网格、材质和锚点；不得在导入节点上绑定玩法脚本。
- 锚点名称大小写必须精确匹配 `Grip`、`Placement`、`Spout`、`FillOrigin`、`Interaction`。

### 5.3 美术评审

- 检查低多边形复古语言、远距识别和明确轮廓。
- 检查木材、铜/黄铜/暗银、玻璃等材质归属；采用手绘基础色、AO 辅助和简单 PBR 参数。
- 磨损必须服务于“经营多年、被时间留下痕迹”，不得使用无目的随机噪点堆叠。
- 现实层检查暖色生活感；眼镜层默认复用几何并通过材质覆盖表现低饱和、冷静和细节暴露。
- 设计案中的“透明量杯”仅作为通用示例；当前双头量酒器先制作金属候选，最终材质在阶段 1 评审锁定。

### 5.4 交互验收

- 按资产适用性检查左右手握持、手持遮挡、摆放稳定、砧板槽位和普通台面防重叠。
- 容器检查 `FillOrigin`、可视容积和内容物不穿模；倾倒工具检查 `Spout` 与操作轴向。
- 固定站点检查交互焦点、抽屉/柜门净空、投放/取料范围和玩家通行。
- 交互校准不得改变配方、动作许可、站点 handler、提示、数值或玩法状态归属。

### 5.5 接入验收

- GLB 只作为手写玩法包装场景下的视觉子场景。
- 包装场景持有碰撞体、稳定 ID、必要的锚点修正、交互脚本和眼镜材质覆盖。
- `tools/validate_assets.py assets/asset_manifest.json --allow-placeholders` 必须保持 0 错误。
- 对应候选只有在运行与视觉复核通过后才能去掉 `placeholder`；灰盒在此之前继续作为回退。

### 5.6 运行验收

- 完整覆盖接单前自由制作、正确冰美式流程、错误工具/材料、比例偏差、手动清废和重做。
- 覆盖左右手、三种量酒器换端、研钵/研杵组合、冰夹/冰桶、量酒器/水壶、滤具/高球杯组合。
- 现实世界与眼镜世界分别截取实际 Forward+ 画面，检查尺度、可读性、材质、灯光、模糊和交互提示。
- 自动化通过不能替代主观握持手感、美术风格和第一人称遮挡验收。

## 7. Git 与资产交付规则

- 建模源文件由美术侧归档；未另行批准前，不把 `.blend` 源文件直接纳入游戏仓库。
- 游戏仓库只接收批准的 GLB、纹理、资产清单路径、包装场景和验收记录。
- 每件资产必须保持稳定 ID；替换占位模型只能通过资产清单和包装场景完成，不改写配方或交互逻辑。
- 本计划文档的首次提交仅包含计划与进展交接文档，不包含现有 `export_presets.cfg` 用户改动，也不推送。
