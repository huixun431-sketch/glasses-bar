# 第二阶段手持核心工具资产设计

- 日期：2026-08-02
- 状态：设计已批准，独立规格审查已通过，等待用户书面复核
- 权威上游：`docs/CORE_INTERACTION_ASSET_MODELING_PLAN.md`

## 1. 目标与范围

第二阶段制作以下五件手持核心工具的低多边形米制 GLB、PBR 材质、稳定锚点与 Godot 手写包装场景：

- `traditional_filter`
- `bean_scoop`
- `ice_tongs`
- `jigger_small`
- `jigger_large`

本阶段只替换这五件资产的视觉表现，不改变既有玩法状态、配方、容量、平衡、输入、左右手规则、液体逻辑或双世界合同。资产仍属于 M1 技术／材质样件，不代表最终美术定稿。

## 2. 已批准的视觉方向

### 2.1 `traditional_filter`

- 采用已批准的“紧凑金属滴滤杯”方向。
- 主轮廓为低矮滤杯、短侧握把、可读网面和明确的底部过滤出口。
- 使用低饱和暖金属色与细拉丝表面；不得依靠高频纹理表达金属。
- 左手握持时不得大面积遮挡视野；放在砧板后必须稳定，并与高球杯形成清楚的过滤组合关系。
- 不把概念轮廓扩展成未经批准的支架、布袋或长柄筛网结构。

### 2.2 `bean_scoop`

- 使用清楚的铲腹与短柄轮廓，装载区域必须从第一人称视角可见。
- 使用深色旧钢色与缎面反射；旧钢仅指受控色值和较宽高光，不增加锈蚀、污渍或叙事性磨损。
- 右手握持；轮廓必须与双头量酒器明显不同。
- `FillOrigin` 位于可读的铲腹装载区域，并维持现有“一次只承载一种原料”的玩法合同。

### 2.3 `ice_tongs`

- 使用清楚的 U 形弹性轮廓、可辨认夹口和明确夹取方向。
- 使用与豆铲同组的深色旧钢色，但保留缎面高光以确保暗场可读。
- 右手握持；不得依靠齿纹等微小细节才能识别。
- 必须适配冰桶抽屉净空、现有取冰方向和载冰落台限制。

### 2.4 `jigger_small` 与 `jigger_large`

- 从已批准的 `jigger_medium` 双头量酒器母版衍生，不重新设计量酒器家族。
- 保留亮银金属、明确杯沿、腰环与双头轮廓；金属高光必须在 Godot 暗场中清楚可见。
- 小号、大号通过整体高度、杯口和体量差异远距可辨，同时保持相同低多边形语言。
- 不为两件变体发明正式容量标记、刻度或新的外观规则。

## 3. 材质映射

采用用户批准的 B 与 C 混合方案中的“混合 C”：颜色分组与表面粗糙度共同承担识别。

| 资产 | 色彩分组 | 表面关系 | 识别目标 |
|---|---|---|---|
| `traditional_filter` | 低饱和暖金属 | 细拉丝、中等宽高光 | 突出传统器具身份与过滤出口 |
| `bean_scoop` | 深色旧钢 | 缎面、宽而柔和的高光 | 与量酒器区分且保持装载区可读 |
| `ice_tongs` | 深色旧钢 | 缎面、夹臂边缘高光 | 暗场中仍能读出 U 形与夹口 |
| `jigger_small` | 亮银 | 延续中号量酒器的抛光／拉丝混合高光 | 保持家族感并显示较小体量 |
| `jigger_large` | 亮银 | 延续中号量酒器的抛光／拉丝混合高光 | 保持家族感并显示较大体量 |

所有材质均以 Blender 内嵌 PBR 参数为交付基线；现实世界与眼镜世界的覆盖材质仍由手写 Godot 包装和现有表现层负责。不得通过纯黑、纯白或缺少环境反射时完全失读的极端物理值冒充金属质感。

## 4. 坐标、锚点与包装合同

- 使用米制；应用对象变换后导出 GLB。
- 保持项目现有 Blender／Godot 坐标约定与阶段 1 生成器的导出方式，不在本阶段更改资产坐标基线。
- 实施计划必须从阶段 1 生成器和已批准的 `jigger_medium` 读取目标尺寸与锚点方向，尤其不得凭新假设重建双头量酒器约定。
- GLB 只作为手写玩法包装场景的视觉子场景；碰撞、脚本、稳定 ID、状态和材质覆盖不得直接挂在导入根节点上。
- 每件资产保留稳定根 ID，并通过资产清单映射到包装场景。
- 必需锚点如下：

| 资产 | 必需锚点 | 关键方向 |
|---|---|---|
| `traditional_filter` | `Grip`、`Placement`、`Spout`、`Interaction` | 左手握持、砧板落位、底部过滤出口、高球杯组合位置 |
| `bean_scoop` | `Grip`、`Placement`、`FillOrigin` | 右手握持、稳定落位、铲腹装载区 |
| `ice_tongs` | `Grip`、`Placement`、`Interaction` | 右手握持、稳定落位、夹口中心与夹取方向 |
| `jigger_small` | `Grip`、`Placement`、`FillOrigin`、`Spout` | 双头换端、取水／倾倒方向 |
| `jigger_large` | `Grip`、`Placement`、`FillOrigin`、`Spout` | 双头换端、取水／倾倒方向 |

## 5. 生产顺序与审核门

采用用户批准的“先轮廓成组，再统一精修”方案。

### 5.1 阶段 2A：统一轮廓阻塞

同步完成五件资产的比例、主要轮廓、接触面、握持方向和全部必需锚点。此时只做判断轮廓所需的低细节几何，不进入最终材质或装饰细节。

**检查点 1：Blender 队列审核**

必须向用户展示同一中性灯光、同一比例参照下的五件资产队列，至少包含正面与三分之四视角；同时显示中号量酒器或统一尺寸卡作为家族与尺度参照。用户检查：

- 五件资产远距轮廓是否互相区分；
- 小／中／大量酒器的家族关系和尺寸差是否清楚；
- 过滤器、豆铲和冰夹的操作方向是否明确；
- 是否存在明显手持遮挡、比例或落位问题。

用户未批准前不得进入材质精修和 Godot 正式替换。

### 5.2 阶段 2B：材质、导出与资产交付

检查点 1 通过后，完成暖金属、深色旧钢与亮银材质；清理法线、接缝、底面、原点和低多边形轮廓；导出 GLB；建立或更新手写包装场景、资产清单与稳定映射。

这一步不得提前移除灰盒回退。只有经过导入、包装和实景检查的资产才能改为非占位状态。

### 5.3 阶段 2C：Godot 实景集成

将五件包装场景接入现有世界与手持表现，并检查：

- 桌面／砧板摆放与碰撞关系；
- 左右手遮挡、握持姿态与倾倒方向；
- 过滤器底部出口与高球杯组合位置；
- 豆铲装载区、冰夹夹口与冰桶抽屉净空；
- 现实世界和眼镜世界的材质、标签与非交互边界。

**检查点 2：Godot 世界／手持审核**

必须运行实际 Godot Forward+ 项目，并向用户展示：

- 五件资产的世界摆放截图；
- 左右手关键握持截图；
- 暖金属、深色旧钢与亮银在实际吧台灯光下的同屏截图；
- 过滤器与高球杯、冰夹与冰桶的关键组合截图；
- 必要时补充眼镜世界截图以验证覆盖材质和观察边界。

用户未批准前不得把第二阶段报告为完成或进入下一资产阶段。

## 6. 技术与玩法边界

- 保持 `ToolVisualLibrary`、`ToolInteractable`、`HeldToolPresenter` 和现有包装优先／灰盒回退合同。
- 不修改配方、容量、平衡、顾客故事、动作提交时机或液体状态语义。
- 现实世界保持可交互；眼镜世界保持观察用途并共享唯一玩法状态。
- 不直接修改导入 GLB 生成的 Godot 资源。
- 不删除其他 7 件仍处于占位状态的资产，也不提前开始阶段 3。
- 本阶段不增加骨骼、IK、动画系统或新的运行时材质框架。

## 7. 验证与完成条件

第二阶段只有在以下条件全部满足后才能标记完成：

1. 五件资产在 Blender 同屏时轮廓、尺度与材质分组清楚。
2. 所有必需锚点存在、命名稳定、方向正确；米制、原点、变换、网格和内嵌 PBR 通过资产验证。
3. Godot 中桌面摆放稳定、手持无遮挡，过滤出口、装载区和夹口方向明确。
4. 暖金属、深色旧钢与亮银在实际吧台灯光下均具有明确的金属高光。
5. 现实世界／眼镜世界继续共享唯一玩法状态，眼镜世界不获得制作交互。
6. 资产验证器对全部 16 项报告 0 错误；本阶段五项 GLB 为 `OK`，其他未制作项仍保持占位。
7. 领域测试、Debug／Release 构建、Godot 导入、烟雾测试、阶段 2 资产集成测试、输入集成和完整流程集成全部通过。
8. 两个视觉检查点均获得用户明确批准，状态文档、变更日志、上下文交接与 `progress.md` 已更新。

## 8. 非目标

- 最终美术定稿或全套工具材质重制；
- 正式容量、刻度、配方或平衡规则；
- 站点资产、吧台结构或环境扩展；
- 新的玩法动作、自动过滤、自动取料或眼镜世界交互；
- 阶段 3 及之后的资产制作。
